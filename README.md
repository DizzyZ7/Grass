## Новое в 0.4 — живые лужайки и персональные экспедиции

- **Погода каждый день:** пять оригинальных погодных состояний — солнечная отладка, ветер перемен, дождь из облака, ночь светлячков и полярный продакшен. Прогноз детерминирован по UTC-дню и локации, один для всех игроков, без геолокации или сторонних API. Canvas рисует дождь, свечение, северное сияние и усиленный ветер; настройки сниженной анимации и недорогих смартфонов сохранены.
- **Полевой журнал:** ежедневная персональная экспедиция из пяти сюжетных задач; выбранное задание и целевая локация фиксируются при первом открытии, так что переход между мирами не перетасовывает награду. Все условия вычисляются на сервере по принятым касаниям и завершенным сессиям. XP выдается однократно под блокировкой строки игрока.
- **Миграция `0004_field_weather`:** отдельная таблица `field_missions` с уникальной парой `(player_id, day)`, дата получения награды и снимок `game_sessions.location_code` на момент начала сессии.
- **Три достижения:** полевой исследователь (3 экспедиции), ветеран (14), секретный значок за реальную **в игровом мире** дождливую сессию с 40 подтвержденными касаниями.
- **Надежность:** обработка UTC-перехода в открытой Mini App, пауза Canvas при скрытой вкладке, защита от второго одновременно удерживаемого пальца. Никаких новых разрешений и платных сервисов.

## Что нового в этапе 3: социализация без выхода из Telegram

[Посмотреть демонстрационную PNG-карточку](docs/assets/share-card-demo.png) (цифры на образце вымышлены).

- **PNG-карточка** 1080×1350: весь рисунок (включая векторную траву) строится Canvas 2D на устройстве игрока. Web Share API предлагает отправить PNG при поддержке клиента; в Telegram WebView без такой возможности доступны предпросмотр, сохранение/удержание картинки и отдельный текстовый шаринг. Сервер не получает PNG и не нуждается в стороннем сервисе рендеринга.
- **Публичный профиль**: имя, подтвержденные сервером касания, уровень, достижения, серия, принятые приглашения. Игрок может отключить публичность: его нет в таблице лидеров, посторонние получают 404 на странице профиля; владелец по-прежнему видит свои данные.
- **Персональные приглашения** без навязчивых ограничений и XP-бонуса: при первом подписанном входе Telegram Mini App сервер читает `start_param=ref_<telegram_id>`. Только уже существующий пользователь может быть приглашающим; за первое приглашение открывается косметическое достижение. Для `?startapp=` нужно настроить Main Mini App через BotFather. Простая кнопка Web App в меню бота может открывать игру, но сама по себе не активирует персональные приглашения.
- **Недельные испытания**: 500 засчитанных касаний, 4 законченные сессии, 2 находки. XP выдается отдельно по каждому испытанию один раз за UTC-неделю, повторный запрос идемпотентен. Пропущенная неделя не уничтожает общий прогресс.
- **Секретные достижения**: 404 подтвержденных касания, 1024 в одной сессии, ночная и выходная экспедиции. Недоступные секреты не раскрываются в каталоге API до открытия.
- **Данные:** Alembic `0003_social` добавляет приватность, атрибуцию приглашений с FK `ON DELETE SET NULL`, недельные награды и индексы. Один Docker-контейнер приложения, внешний PostgreSQL; никакой жесткой привязки к провайдеру.

## Быстрый запуск в браузере — без BotFather

Для локальной проверки игры можно использовать только тестового пользователя `X-Demo-User`. **Не включайте `DEV_MODE` на публичном сервере.**

Нужно установить Python 3.12+, Node 22+, Docker + Compose (для PostgreSQL). Создайте `.env` на основе `.env.example`. Для локальной проверки задайте `DEV_MODE=true`, оставьте `BOT_TOKEN`, `WEBHOOK_SECRET` и `PUBLIC_BASE_URL` пустыми.

```bash
cp .env.example .env
# в .env поставьте DEV_MODE=true и PUBLIC_BASE_URL=
docker compose up --build
```

Откройте `http://localhost:8000`. Docker Compose запускает PostgreSQL отдельно для локальной разработки, **для публичного сервера нужна отдельная постоянная PostgreSQL**. Если нужен интерфейс с hot reload:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
# PostgreSQL должен быть запущен; DATABASE_URL берется из .env
alembic upgrade head
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
cd frontend && npm install && npm run dev
```

Фронтенд доступен по `http://localhost:5173`; Vite проксирует `/api` к FastAPI. Production без Telegram-подписи вернет 401, локальная демо-авторизация существует **только при явном DEV_MODE=true**.

## Telegram и независимое развертывание

1. Через [@BotFather](https://t.me/BotFather) создайте собственного бота. Никогда не публикуйте токен.
2. Подготовьте PostgreSQL 15+ с постоянным диском, регулярными резервными копиями и TLS (для внешней БД).
3. На собственном VPS, в Docker-хостинге или Kubernetes подключите репозиторий `https://github.com/DizzyZ7/Grass`, ветка `main`; соберите корневой `Dockerfile`. HTTPS-терминацию настройте через обратный прокси (Caddy, nginx) или возможности выбранной платформы. Порт контейнера задается `PORT`.
4. Укажите секреты в переменных окружения, не в git:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен от BotFather |
| `WEBHOOK_SECRET` | `python -c "import secrets;print(secrets.token_urlsafe(32))"` |
| `PUBLIC_BASE_URL` | HTTPS URL публичного домена, без `/` в конце |
| `DATABASE_URL` | `postgresql+psycopg://USER:PASS@HOST:5432/DB?sslmode=require` |
| `PORT` | Порт, например `8000` |
| `DEV_MODE` | `false` |

5. Перед стартом контейнер выполняет `alembic upgrade head`. FastAPI слушает `0.0.0.0:${PORT}` и на старте сам устанавливает Telegram webhook на `${PUBLIC_BASE_URL}/api/telegram/webhook` с секретным заголовком. Держите **одну реплику** до внедрения распределенного rate limiter и отдельного migration job.
6. Проверьте `${PUBLIC_BASE_URL}/healthz`, Telegram `/start`, авторизацию Mini App, сохранение сессии и открытие после перезапуска. По желанию задайте в BotFather прямую Mini App-ссылку.

[Официальная документация Telegram initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

### Проверка социального режима

После первой настройки Main Mini App в BotFather откройте ссылку игрока `https://t.me/USERNAME?startapp=ref_TELEGRAM_ID`. На **самом первом** авторизованном открытии нового игрока сервер проверит подписанный Telegram `start_param`, запишет `referrer_id` и откроет пригласившему косметическое достижение. Произвольный query-параметр URL и `initDataUnsafe` не принимаются как доказательство приглашения. Старые игроки не могут перезаписывать уже установленное приглашение. Если Main Mini App еще не настроена, обычное приглашение поделится ссылкой на игру без начисления реферала.

В разделе «Друзья» можно скрыть свой профиль из рейтингов и снова включить публичность. PNG-карточка генерируется из сохраненных сервером достижений на устройстве: при отсутствии `navigator.share({files})` потребуется самостоятельно сохранить изображение из предпросмотра.

### Диагностика

- **502 / падение контейнера:** проверьте логи подключения PostgreSQL и миграций, `PORT`, HTTPS-домен, существование собранного `frontend/dist/index.html`.
- **401:** Mini App открыт вне Telegram или просрочено `initData` (24 ч). Закройте и откройте бот заново. Не включайте публичную демо-авторизацию как обход.
- **403 на webhook:** Telegram заголовок не совпадает с `WEBHOOK_SECRET`. Убедитесь, что PUBLIC_BASE_URL соответствует именно вашему домену.
- **Касания не начислены:** сервер ограничивает скорость и общую награду сессии. Повторная отправка уже сохраненного пакета возвращает чек, но не повторяет награду.
- **Перед перезапуском:** проверьте, что PostgreSQL расположен вне эфемерной файловой системы контейнера, а резервное копирование БД включено.

**Безопасность.** Сервер доверяет только подписанному `Telegram.WebApp.initData`; `initDataUnsafe`, счетчикам XP с клиента и словам «я точно потрогал» — не доверяет. Запросы пакуются, награды ограничены серверными часами, операции записываются с UUID для защиты от повторов. Локальный rate limiter не распределен: для масштабирования на несколько реплик понадобится Redis/общий edge-limit, а миграции нужно вынести в отдельный job. Абсолютно доказать физическое прикосновение к экрану невозможно, задача — уменьшить накрутку без ухудшения обычной игры. Приложение не запрашивает геолокацию, камеру или контакты.
