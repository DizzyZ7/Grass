## Быстрый запуск в браузере — без BotFather

Для локальной проверки игры можно использовать только тестового пользователя `X-Demo-User`. **Не включайте `DEV_MODE` на публичном сервере.**

Нужно установить Python 3.12+, Node 22+, Docker + Compose (для PostgreSQL). Создайте `.env` на основе `.env.example`. Для локальной проверки задайте `DEV_MODE=true`, оставьте `BOT_TOKEN`, `WEBHOOK_SECRET` и `PUBLIC_BASE_URL` пустыми.

```bash
cp .env.example .env
# в .env поставьте DEV_MODE=true и PUBLIC_BASE_URL=
docker compose up --build
```

Откройте `http://localhost:8000`. Docker Compose запускает PostgreSQL отдельно для локальной разработки, **на Bothost база не предоставляется автоматически**. Если нужен интерфейс с hot reload:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
# PostgreSQL должен быть запущен; DATABASE_URL берется из .env
alembic upgrade head
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
cd frontend && npm install && npm run dev
```

Фронтенд доступен по `http://localhost:5173`; Vite проксирует `/api` к FastAPI. Production без Telegram-подписи вернет 401, локальная демо-авторизация существует **только при явном DEV_MODE=true**.

## Telegram и Bothost

1. Через [@BotFather](https://t.me/BotFather) создайте собственного бота. Токен никому не отправляйте; сохраните в защищенных переменных окружения.
2. Создайте **внешнюю PostgreSQL**, например на отдельном managed-тарифе или собственном сервере. Уточните, есть ли PostgreSQL в вашем конкретном тарифе Bothost. Настройте TLS к базе по требованиям провайдера (например, `?sslmode=require`).
3. В Bothost создайте сервис из репозитория `https://github.com/DizzyZ7/Grass`, ветка `main`, режим **Custom Dockerfile**, путь `Dockerfile`, включите домен и HTTPS, направьте HTTP-трафик на **PORT** (обычно `8000`). Для одного запущенного экземпляра достаточно 512–1024 МБ памяти в зависимости от нагрузки.
4. В переменные окружения Bothost внесите следующие значения (без кавычек):

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Секретный токен бота от BotFather |
| `WEBHOOK_SECRET` | `python -c "import secrets;print(secrets.token_urlsafe(32))"` |
| `PUBLIC_BASE_URL` | **Точный** выданный HTTPS URL без `/` в конце |
| `DATABASE_URL` | `postgresql+psycopg://USER:PASS@HOST:5432/DB?sslmode=require` (пример) |
| `PORT` | Выданный Bothost порт или `8000` |
| `DEV_MODE` | `false` |

5. Запустите деплой. Контейнер перед запуском выполняет `alembic upgrade head`, затем сервер слушает `0.0.0.0:${PORT}`. После старта FastAPI автоматически устанавливает Telegram webhook на `${PUBLIC_BASE_URL}/api/telegram/webhook` с заголовком `X-Telegram-Bot-Api-Secret-Token`, а также кнопку в меню бота.
6. Проверьте HTTPS `${PUBLIC_BASE_URL}/healthz`, откройте бота и нажмите **«НАЧАТЬ СОЦИАЛИЗАЦИЮ»**. В BotFather при необходимости задайте Mini App URL и короткое имя для прямых `startapp` ссылок. Не устанавливайте webhook отдельно, приложение делает это само.

Документация: [Bothost / домены, Dockerfile, Mini App](https://bothost.ru/docs/) · [Telegram / проверка initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

### Диагностика

- **502 / падение контейнера:** проверьте логи подключения PostgreSQL и миграций, `PORT`, HTTPS-домен, существование собранного `frontend/dist/index.html`.
- **401:** Mini App открыт вне Telegram или просрочено `initData` (24 ч). Закройте и откройте бот заново. Не включайте публичную демо-авторизацию как обход.
- **403 на webhook:** Telegram заголовок не совпадает с `WEBHOOK_SECRET`. Убедитесь, что PUBLIC_BASE_URL соответствует именно вашему домену.
- **Касания не начислены:** сервер ограничивает скорость и общую награду сессии. Повторная отправка уже сохраненного пакета возвращает чек, но не повторяет награду.
- **Перед перезапуском:** проверьте, что PostgreSQL расположен вне эфемерной файловой системы сервиса Bothost, а резервное копирование БД включено.

```text
tests/                       auth, экономика, API, replay

```

**Безопасность.** Сервер доверяет только подписанному `Telegram.WebApp.initData`; `initDataUnsafe`, счетчикам XP с клиента и словам «я точно потрогал» — не доверяет. Запросы пакуются, награды ограничены серверными часами, операции записываются с UUID для защиты от повторов. Локальный rate limiter не распределен: для масштабирования на несколько реплик понадобится Redis/общий edge-limit, а миграции нужно вынести в отдельный job. Абсолютно доказать физическое прикосновение к экрану невозможно, задача — уменьшить накрутку без ухудшения обычной игры. Приложение не запрашивает геолокацию, камеру или контакты.
